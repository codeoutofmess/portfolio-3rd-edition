<Step n="01" title="Why I built it">
It was the second most common backend stack in the roles I was looking at, and I hadn't used it at work. A real app teaches more than a tutorial.
</Step>

<Media src="/images/work/desklog/ticket-list.png" caption="Tickets, filterable by status and priority." />

<Step n="02" title="Two bugs">
A duplicate email and a validation error both came back as 403, because Spring Security was blocking its own error page. Missing tokens also returned 403 instead of 401 until I told it the difference. Neither shows up by reading the code.
</Step>

<Media src="/images/work/desklog/ticket-detail.png" caption="A ticket's status control and comment thread." />

<Step n="03" title="A moving target">
The plan said Spring Boot 3. By the time I started, the project generator only made Boot 4, so I checked what had changed instead of trusting older tutorials.
</Step>

<Media src="/images/work/desklog/architecture.svg" caption="React on Vercel, the API in Docker on Render, data in Postgres." />

<Step n="04" title="Where it stands">
Live on a real Postgres database that keeps its data, so the demo tickets are only added when it's empty. Any signed in user can change any ticket, which is fine for a project built to learn the stack.
</Step>
