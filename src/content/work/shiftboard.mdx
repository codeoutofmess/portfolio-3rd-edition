<Step n="01" title="Why I built it">
Datacom, Sandfield, AUT and others all listed ASP.NET Core with React. Rather than claim it on an application, I built something real with it, from scaffold to live deploy.
</Step>

<Media src="/images/work/shiftboard/week-view.png" caption="The week view, across Wellington CBD and Lower Hutt." />

<Step n="02" title="One real rule">
An employee can't be booked on two shifts that overlap. Every create and edit checks it, and a shift being edited doesn't clash with itself. Anyone signed in can see the roster, but only admins can change it.
</Step>

<Media src="/images/work/shiftboard/new-shift-form.png" caption="Adding a shift checks the times before it reaches the API." />

<Step n="03" title="Bugs I only found by running it">
The week header showed garbage because of a date format quirk. And a query that compiled fine would have crashed the first time anyone loaded shifts, because the database can't run a C# method.
</Step>

<Media src="/images/work/shiftboard/architecture.svg" caption="React on Vercel, the API in Docker on Render." />

<Step n="04" title="Where it stands">
Live, with a demo roster that resets whenever the server restarts. Permissions are by role only, not by who owns a shift.
</Step>
